# SigNoz (local observability backend)

A self-hostable, OpenTelemetry-native backend for viewing this app's traces,
logs, metrics, and **grouped exceptions with stack traces**. Everything the app
emits (see `internal/observability`) is consumed here with no code changes —
just point the app's OTLP exporter at it.

These Compose files were generated by SigNoz's [Foundry](https://signoz.io/docs/install/docker/)
installer (`foundryctl forge` from `casting.yaml`) and vendored so developers
need only Docker — no `foundryctl` install. To bump SigNoz, re-run Foundry and
re-vendor (see "Regenerating" below).

## Requirements
- Docker + Docker Compose v2
- ~4 GB RAM free for the stack (ClickHouse is the heavy part)

## Quick start (from the repo root)

```bash
make signoz-up      # start the stack (ClickHouse, collector, UI, Postgres, keeper)
make signoz-setup   # REQUIRED first run: create the admin/org (see below)
make run-otlp       # run the app pointed at SigNoz (needs your .env Alpaca creds)
```

Then open the UI at **http://localhost:8080** and log in with the credentials
printed by `make signoz-setup` (default `admin@alpaca.local` / `Alpaca12345!`).
Errors appear under **Exceptions**; traces under **Traces**.

`make signoz-down` stops the stack (data persists in named volumes;
`docker compose down -v` from `deploy/signoz` wipes it).

## Why `make signoz-setup` is required

SigNoz's collector is **OpAMP-managed**: it fetches its pipeline (including the
OTLP receivers on 4317/4318) from the backend at runtime. The backend refuses to
configure the collector until an **organization exists** — until then the OTLP
ports accept TCP (docker-proxy) but the receiver isn't running, so every export
**fails silently** and nothing lands. Symptom in `make signoz-logs`:
`cannot create agent without orgId`. `make signoz-setup` creates the first
admin/org via the API (idempotent), after which the collector opens its
receiver within ~30s. You can also do this once by hand via the UI onboarding.

## Ports
- `8080` — SigNoz UI / API (**collides with the app's default port**; `make run-otlp` runs the app on `8081`)
- `4317` — OTLP gRPC ingestion
- `4318` — OTLP HTTP ingestion (the app's exporters use this)

## Pointing the app at it manually

```bash
OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4318 PORT=8081 go run .
```

`internal/observability` switches from stdout to OTLP whenever
`OTEL_EXPORTER_OTLP_ENDPOINT` is set — traces, logs, AND metrics all flow to
SigNoz (unlike Sentry, which doesn't take OTLP metrics).

## Notes
- Images are pulled as `:latest` (as Foundry generates). For reproducible CI,
  pin the `signoz/signoz` and `signoz/signoz-otel-collector` tags in `compose.yaml`.
- `casting.yaml` is the Foundry source config, kept for regeneration.

## Regenerating (bumping SigNoz)

```bash
curl -fsSL https://signoz.io/foundry.sh | bash          # installs foundryctl
foundryctl forge -f deploy/signoz/casting.yaml -p /tmp/pours
cp -r /tmp/pours/deployment/. deploy/signoz/             # re-vendor compose + configs
```
